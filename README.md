# Abington Banking Account

This is a local-preview banking website that simulates an upgraded private-banking workspace with:

- a public homepage with login and create-profile entry points
- a separate administrative approval dashboard at `admin.html`
- two separate preview roles: customer account access and administrative OTP inbox access
- seeded relationship balance around `$479,800`
- internal transfers
- scheduled payments
- recurring transfers
- card hold creation, capture, and release
- card controls
- mock statement generation
- visible account operator funding with audit logging
- notifications and activity timeline
- server-generated transfer approval codes in a local outbox preview
- receipt PDF generation plus local email preview artifacts for transfer receipts

## Safety note

The interface uses fictional Abington branding for design review, but it remains clearly labeled as a prototype. It does not connect to any real institution or financial rail.

## Run locally

From this folder, use the local preview server instead of `python -m http.server`:

```powershell
npm start
```

Then open:

[http://localhost:8080](http://localhost:8080)

You can also run:

```powershell
node server.js
```

## Local preview delivery

- Approval codes are generated by the Node server, not the browser.
- All OTP previews are redirected to the fixed local inbox target `abingtonbank@aol.com`.
- No live email provider is connected.
- Each approval code email preview is written to `outbox/previews/email/otp`.
- Each receipt email preview is written to `outbox/previews/email`.
- Each generated receipt PDF is written to `outbox/previews/pdf`.

The homepage approval center and receipt panels link to those local preview artifacts.

## Render deployment

This project is now prepared for Render with [render.yaml](/C:/Users/HomePC/Documents/Playground/abington-banking-web/render.yaml).

- Service type: Render web service
- Runtime: Node
- Start command: `npm start`
- Health check: `/api/health`
- Suggested service name: `abingtonbank`

Render's current docs say web services receive an `onrender.com` subdomain, and a Blueprint can define fields such as `name`, `runtime`, `buildCommand`, `startCommand`, and `healthCheckPath`. If `abingtonbank` is available in your Render account, the public URL can be close to `https://abingtonbank.onrender.com`. If that exact service name is already taken, Render will require the nearest available variation.

Important deployment note:

- This simulator stores OTP previews, receipt previews, and some transfer session state in the app filesystem and memory.
- On Render, that works for demo sessions, but those artifacts can reset after restarts or redeploys.
- If you want stable persistent inbox/receipt/session history, the next step is moving those items into a database or durable object store.
